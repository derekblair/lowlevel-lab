# part 03 — quine-relay (AGENTS.md)

Part of **lowlevel-lab** (see ../../AGENTS.md). Author-lane build of the P3-slot
replacement C12 (APPROVED N3, REVIEW-01 §6.1). A cross-ISA machine-code quine
relay: x86-64 ELF → AArch64 ELF → x86-64 ELF, byte-exact.

- **What:** `build_fixpoint.py` (stdlib; hand-emits both code blocks + ELF
  headers + the shared payload P, writes stage0), `verify.sh` (one relay cycle +
  all the C12 checks), `Makefile`. README explains the payload fixed point;
  RUN.md is the verbatim evidence.
- **Build/run:** `make` (= `./verify.sh`): builds stage0, runs stage0→stage1
  (native x86) →stage2 (stage1 under qemu-aarch64), checks the fixed point.
  Present tools only: python3 stdlib, qemu-aarch64, binutils (objdump/readelf),
  strace. No root, no installs.
- **Novel observable (R4):** `sha256(stage0) == sha256(stage2)` across the
  x86-64→AArch64→x86-64 cycle, with each stage a single-ISA ELF. Proven by the
  `VERDICT PASS` lines in RUN.md §1.
- **Relay, not polyglot (C12-3):** the other ISA's bytes live in a stage only as
  data in P; no stage executes the other ISA's code.
- **Safety (C12-2):** each stage only `write(1,…)` + exit (strace / qemu -strace
  verified); no stage writes or execs itself; the harness runs the emitted
  stages. Benign.
- **Emulation labelled (C12-4/R10):** stage1 runs under qemu-aarch64, not ARM hw.
- **Artifacts:** stage0/1/2 are generated (reproducible via `make`); `make
  clean`-able; not build inputs (stage0 is generated by build_fixpoint.py).
